# 方法学短文骨架：「计算工具的自证伪基础设施」

> 来源：第三轮评审 §F R3——"你们三个 skill 正在独立收敛出同一套元科学实践，
> 建议把它抽出来写成一篇独立短文，比任何一个单工具论文都更有引用潜力"。
> 本文档只做**骨架 + 每节必须引用的自有证据**，不写正文。
>
> 定位：**不是**软工论文（不讨论 CI/CD），**不是**元科学综述（不重述 reproducibility crisis），
> 而是"**一个计算工具如何被设计成能推翻自己**"的可操作清单 + 案例。

---

## 0. 一句话论点

> 大多数计算工具的自证是**充分性测试**（能跑通、能复现、指标达标）；
> 真正稀缺的是**必要性测试**——设计出"如果我的核心主张是错的，这个实验会告诉我"的装置。
> 本文给出六个这样的装置，并报告它们在本工具上**真的推翻了哪些自家主张**。

**为什么这个论点站得住**：因为六个装置里有 5 个的产出是**负面的**（下表）。
只报正面结果的框架不能声称自己有自证伪能力。

## 1. 六个装置（每个都要能独立被抄走）

| # | 装置 | 一句话定义 | 在本工具上推翻了什么 |
|---|---|---|---|
| D1 | **空心 ✅ 清查 + ✅ 必须附产物** | 任何 ✅ 必须绑①产物路径②产物内**字面量**数字，由脚本逐条核对 | 查出 R14/R19/R20 三项标 ✅ 但产物从未生成；改为机器可判 |
| D2 | **负结果 → 默认配置** | 每条负结果必须落成一个**默认值**，否则负结果只对读者生效、对自己不生效 | 8 条负结果进 `DEFAULTS`，"准入层默认关闭"成为可断言事实 |
| D3 | **功效驱动弃权** | 连**完美模型**都过不了的检验，不得判模型有病 | DILI 的 MMP 从"模型迟钝"改判 `insufficient_power`（31 对 vs 需 61） |
| D4 | **规格敏感性（multiverse）** | 把分析选择全展开，报**方向翻转率** | 216 规格翻转率 0.398（有效 n=20，非 216 次独立实验）；~~据此改写为条件性优势区~~ **【2026-11-04 撤回 / C18 + 外审 A】**：该改写基于会计恒等式，不得作为结论 |
| D5 | **时间/外源留出 + 标签自审** | 外源结论必须能回答"这批数据真的是后见的吗" | **查出 "post-cutoff" 标签是错的**（服务端年份过滤失效，实际是时间混合集）→ 强表述撤回 |
| D6 | **阈值冻结审计** | 每条阈值登记来历（literature / calibrated / ad_hoc），漂移即阻断 | 11 条阈值分级；`ad_anchor 0.35` 明确标"不冻结"并给出理由 |

**D5 是这一套里最贵也最值钱的一条**：它不是"加一个外源验证"，
而是"**验证你的验证**"。本工具的 D5 直接推翻了自己的头条结论，见 §3。

## 2. 三条设计原则（比装置更抽象，是本文的"方法"层）

### P1 让"绕过"比"遵守"更贵

红线如果只写在文档里，绕过成本 = 0。所以每条主张都要有**代码级真源**：
`CLAIMS_REGISTRY.yaml`（数字）→ `NEGATIVE_RESULT_DEFAULTS.yaml`（行为）
→ `THRESHOLD_REGISTRY.yaml`（参数），三者都由发布门禁读取。
删除登记项 = 门禁红；改数字不改产物 = 门禁红。

### P2 对自己和对评审用同一把尺

本工具批评过评审的"近邻代理"会被标签构成抬高相关；
随后自己在算"两源误差相关"时犯了**同一个错**（合并相关 0.845 vs 标签分层内 0.655），
自查后改用分层内相关——**结论从"还行"变成"收益为零"**。
> 原则：任何你用来打别人的方法学批评，先在自己最近的一个数字上跑一遍。

### P3 判决要能被数据改写，而不是被措辞改写

"表述收紧"是最廉价的整改。本工具的 S5 未校准基线实验是反例：
它没有去改措辞，而是**增加一条基线**，结果把"负面结论源于基线过强"这个辩解**否证**了。
> 原则：能加实验就别改措辞；改措辞必须同时说明"为什么这个改动不是修辞"。

## 3. 案例：一次完整的自我推翻（D5 的可读版）

| 阶段 | 内容 |
|---|---|
| 主张 | "外源后见数据上模型崩溃（AUC 0.581 < 平凡基线 0.679），所以域外不该回答" |
| 装置 | 按 Tanimoto 分层，看 AUC 是否随距离单调上升 |
| 初版结果 | 单调上升（0.538→0.630，桶级 ρ=0.90）→ 写下"门的方向正确" |
| **自审触发** | 检查产物 `document_year` 分布，发现 1995–2025 全有 |
| 根因 | 时间条件交给了服务端 `document__year__gte`，**该端点不执行它**（四种取值同一 total_count） |
| 修复 | 本地按 `document_year` 切分 → 三套集合并排 |
| 更正后 | 两个真时间留出切点（≥2021 n=1941 / ≥2023 n=959）**均判 `trend_not_robust`** |
| 结论变化 | 撤回"门精确划界"，改为"域外处处不可用；全拒是**保守的正确**" |
| 代价 | 头条结论变弱 |
| 收益 | 剩下的那半句（域外不可用）**三切点稳健**，比原来更硬 |

> 这一段是全文的核心素材：**它展示了自证伪基础设施的真实成本与真实回报**。

## 5. 投稿策略与最小可行版本

**最小可行版（建议先写这个）**：3500 词，只讲 D1/D3/D5 三个装置 + §3 案例。
理由：三个装置都有**完整的前后对照**（改之前怎样、改之后怎样），而 D2/D4/D6 更像工程实践。

**目标场合**（按匹配度）：
1. 方法学短文 / perspective（如 *Nature Computational Science* comment、*J Cheminform* commentary）；
2. 与主文打包成 "方法 + 元方法" 双篇（主文见 `PAPER_SKELETON_v4.4.md`）；
3. 作为工具文档的"设计根据"章节（零审稿成本，但引用价值低）。

**风险（老实写）**：
- 单工具的经验法则容易被审稿人质疑"n=1 的归纳"→ 必须补**跨工具**证据
  （另两个 skill 的同类实践 = 天然的第二个案例，这是本文能成立的关键）；
- "自证伪"容易被读成"自我批评秀"→ 必须给出**可量化的回报**（如 §3 的"三切点稳健"）。
