# 时间留出 vs 前瞻盲测：纪律文件（R-B 外部评审，2026-11-03）

> **本文件的存在理由**：本包最锋利的一把刀是红线 8（"post-cutoff 数字必须同句标注
> 非预注册前瞻"）。外部评审 R-B 指出：这把刀**正在切自己**——我们在讨论 P2.2 时
> 把 OpenADMET 官方时序切分称为"前瞻"，而按本包自己的标准，它不构成前瞻。
> 一个方法学框架如果在自己的核心概念上偷懒，其余全部论证都失去支点。

## 1. 三种设计的严格界定

| 设计 | 定义 | 它能证明什么 | 它**不能**证明什么 |
|---|---|---|---|
| **内部随机切分**（random split） | train/test 同分布随机划分 | 模型在**同一化学空间**内的拟合优度 | 外推能力、真实部署表现 |
| **时间留出**（temporal holdout） | 按时间戳切分，train 早于 test | 对**时间漂移**的稳健性；比随机切分更强的外部效度 | **前瞻性**：评测方案是在看到 test 集存在之后设计的 |
| **前瞻盲测**（prospective blind test） | 方案先冻结存证 → 之后数据才产生/解封 → 盲态执行 | 真实的"事前承诺"；唯一能支撑"我们的阈值不是事后挑的" | 大样本（时间成本高，n 通常小） |

**关键判据只有一条**：**设计评测方案的人，在设计时是否已经知道测试数据的存在与分布。**
知道 → 最多是时间留出；不知道 → 才可能是前瞻。

## 2. 本包现有证据的诚实归类（逐条）

| 证据 | 现有标签 | 正确归类 | 处理 |
|---|---|---|---|
| TDC 官方切分上的 hERG/DILI/BBB 结果 | 内部效度 | **内部随机切分** | 只能用于"方法在同一空间内有效"，不得称外推 |
| ChEMBL_37 hERG IC50 全集（n=9443） | 曾被标 post-cutoff | **时间混合集**（标签错误，已在 v4.4 §0 自曝） | 只能作为"大样本外部集"，禁止任何时间性表述 |
| y2021 / y2023 切分（n=1941 / 959） | post-cutoff 外源 | **时间留出**（同一数据源、两个切点） | 可用，但必须写"temporal holdout，非预注册前瞻" |
| OpenADMET 官方时序切分（test 20101–27239） | 待做 | **时间留出**（切分由数据发布方固定） | 若用于论文，措辞只能是 temporal holdout；**不满足 v4.0 条件②** |
| 未来：方案冻结 + 新数据解封 | — | **前瞻盲测** | 唯一满足条件②的路径，见 §3 |

## 3. 满足 v4.0 条件② 的最小可行设计（可直接执行）

**前置**：一个"未接触过目标数据"的执行者 E（可以是合作者、也可以是本仓库作者在
**签署承诺书并留存 hash 之后**，但审计上弱一档，须在材料中声明）。

1. **冻结方案**（T0）：把以下内容写成单一文件并计算 sha256，提交第三方存证
   （OSF / Zenodo / 机构 Git 的时间戳提交均可）：
   - 主假设与判读规则（见 `SAP_PROTOCOL.md`）；
   - 代价网格 `c_abstain / c_false_PASS / c_false_FAIL`；
   - 端点清单与阈值表（含 `THRESHOLD_REGISTRY.yaml` 的 hash）；
   - 分析代码的 commit hash；
   - **明确的"失败即结论"条款**：结果不利也必须公布。
2. **等待/解封**（T0 → T1）：目标数据在 T0 之后产生（新文献年份 / 新测定批次 /
   新一批湿实验）。**不得**使用 T0 之前已存在的任何记录。
3. **盲态执行**（T1）：E 按冻结方案跑，不得改阈值、不得改端点、不得换代价。
   允许改**实现 bug**，但必须记录 diff 并说明不影响判读。
4. **全量公布**：无论 Δu 为正为负、无论 gate 是否"失效"，全部数字进
   `references/CLAIMS_REGISTRY.yaml`，正负都进主文。
5. **登记**：在 `PREREG` 记录里写 `anchor_status=ANCHORED`、`anchor_date`、
   `anchor_artifact_sha256`、`prospective_data_window`。

**验收**：`python -m adt.cli prereg --check` 必须同时给出
`claim_allowed=True` 与 `prospective_window_after_anchor=True`；
缺任一条，v4.0 标签不得授予。

## 5. 为什么这条纪律值钱

方法学审稿人最常问的三个问题里，有两个直接对应这里：
"你的阈值是不是看了数据才定的"、"你的外部验证是不是同分布"。
**本包此前的答案分别是"部分是"和"是"**——把它写清楚，比多做一个模型有价值得多；
把它藏起来，一旦被审稿人发现，整篇的可信度归零。
