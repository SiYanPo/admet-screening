# 独立性感知决策表（INDEPENDENCE_DECISIONS）

> 对应处方：**P10（评审 v4.0，解决 C4 高严重度）**。
> 评审原话："材料同时存在 Fisher z 合并（F3）与并查集聚簇权重、endpoint_rho_contraction，
> 三套机制并存，材料未给出'何时用哪套'的决策规则……必须补一张'独立性感知决策表'。"
> 本文件即该决策表，并已纳入 P1 双通道（截断 + 分流，解决 C1/C10 致命）。

## 0. 为什么要这张表
源独立性不是"给一个数字"，而是三个正交维度，各有独立机制，必须在**计票层以唯一入口**汇合，
否则会出现"同一份相关性被三套机制各算一遍、互相矛盾"的灾难（C4）。三个维度：

| 维度 | 机制 | 输入 | 输出 | 代码落点 |
|---|---|---|---|---|
| A. 端点级 ρ 收缩 | `rho_contraction_weight`（P1 新增） | 逐端点 ρ + Fisher z 95%CI | 收缩权重 ∈[0.5,1] 或 `source_conflict` | `adt/independence.py` |
| B. 组冗余降权 | `group_summary` union-find | 同组源间 max_pos_rho | 组权重 ∈[0.5,1] | `adt/independence.py` |
| C. Fisher z 合并 | `source_rho.bootstrap_ci` | 配对样本 | ρ 点估计 + CI(lo,hi) | `adt/source_rho.py` |

**唯一汇合入口＝计票层的有效票数**：`effective_votes` 中每个独立方法组的票数 = `max(维度A权重, 维度B权重)` 的保守取小（见 §3）。

## 1. ρ 三区分流规则（P1 核心，解决 C1/C10）
逐端点读入 ρ 点估计与 Fisher z 95%CI(lo, hi)，按下表分流：

| 区 | 判定 | 计票动作 | 归因/信号 |
|---|---|---|---|
| **ρ < 0**（或 CI 整体为负） | 方向/语义冲突 | **不收缩**（权重=1.0），触发 `source_conflict` | 第七类归因 `source_conflict`；该端点默认 **UNDETERMINED**，action 指向第三源/实测仲裁 |
| **CI 含 0**（lo ≤ 0 ≤ hi） | 方向不确定 | **不收缩**（按 ρ=0 计，权重=1.0） | 显式标注 `no_direction` |
| **ci_lo > 0**（方向确定为正） | 冗余可量化 | 收缩：`w = 1/(1+max(ρ,0))` | `contracted` |

> 旧版（v3.6.2）缺此逻辑：`group_summary` 仅做 0.5–1.0 冗余降权，ρ<0 被当作"低冗余"甚至
> 放大等效票（hERG ρ=−0.574 的 badcase 1 即源于此）。P1 已修复（`rho_contraction_weight` + 回归测试
> `tests/test_rho_contraction.py`：ρ=−0.574 / ρ=−0.999 触发 source_conflict；ρ=+0.594 方向确定时收缩为 0.6274）。

## 2. 维度 B：组冗余降权（union-find 聚簇）
- 同 `independence_group` 内，只看**正相关**：`max_pos_rho`（负相关已归维度 A 的 source_conflict，不再被当作"同组冗余"降权）。
- `max_pos_rho ≤ 0.70` → 权重 1.00（独立）；`0.70–0.90` → 1.00→0.50 线性；`≥0.90` → 0.50（半票）。
- 无配对数据 → 权重 1.00 + `no_rho_data`（保守不降权，但显式标注）。

## 3. 冲突优先级（计票层唯一权重入口）
当维度 A 与维度 B 对同一个"独立方法组"给出不同权重时：
- **取更保守者（更小权重）**：`group_effective_weight = min(A_weight, B_weight)`。
- 若维度 A 返回 `source_conflict` → 该组该端点**直接 UNDETERMINED**，不再进入计票，reason=`source_conflict`。
- 维度 C（Fisher z 合并）是维度 A/B 的**输入生产者**，不是独立的计票层；它的职责是给 A/B 提供带 CI 的 ρ，
  不得用它直接改判。

## 4. 端点级粒度规则
- ρ 一律**端点级**估计与登记（`source_rho` 逐端点输出 `spearman / ci_lo / ci_hi`），禁止跨端点共享一个 ρ。
- "ρ 是数据集条件量，不是普适常数"（见 SOP）：同一对源在不同化学类/数据集上的 ρ 可不同，须分别登记（见 `SOURCE_REGISTRATION_POLICY.md` / L2-3）。
- 某端点无配对 ρ 数据时：维度 A 退化为 `inconclusive`（权重 1.0 + `no_rho_data`），但维度 B 仍可用组冗余；两者都无 → 保守记 1 票并标注。

## 6. v4.4 撤回：「源独立性不可由我方验证」这一结论是错的（第三轮评审 §E2）

### 6.1 撤回的是什么

第二轮评审提出 A1（受控独立性梯度），我方的处置是**降级为"非我方可关闭"**——理由是
"OpenADMET / 自训模型的重叠度无法由我们控制"。第三轮评审明确指出这个定性**应当撤回**：
OpenADMET 的模型权重与训练集清单是**公开**的，我方完全可以自己训练模型并**人为设定重叠比例**。

本轮已按这条路径做完（`run_independence_gradient.py`），所以这不是"接受批评"，是"批评被证实"。

### 6.2 实验设计（单方可行，无需任何外部输入）

| 要素 | 设定 |
|---|---|
| 数据切分 | 同一数据集二分 H1 / H2（互斥） |
| 源 A | H1 ∪ α·H2，α ∈ {0, 0.25, 0.5, 1.0} |
| 源 B | H2（**固定不动**） |
| 重叠度 | 由 α 显式控制 = 两源共享训练样本比例 |
| 重复 | 20 个种子/档，同一批测试分子 |
| 主指标 | **标签分层内**的误差相关 `rho_error_within_label`（理由见 6.3） |

### 6.3 一个必须自我适用的方法学修正（否则实验白做）

首版用**合并**Spearman(e_A, e_B)，α=0 时就得到 0.861——看起来"不共享数据也高度一致"。
这是**假象**：e = p − y 里含共同的 **−y** 分量，两边都减同一个 y，相关自然高。
改为**标签分层内**加权相关后，α=0 的真实基线是 **0.655**。

> 这正是本包对评审 E2"近邻代理"的同一条批评（近邻组共享标签构成 → 相关被抬高）。
> **对自己和对评审必须用同一把尺**，否则 6.2 的结论全部作废。

### 6.4 结果与解读

| α（源 A 与源 B 的共享样本比例） | **0** | 0.25 | 0.50 | **1.00** |
|---|---|---|---|---|
| ρ_error（**标签分层内**，主指标） | 0.6553 [0.616, 0.704] | 0.7982 [0.778, 0.817] | 0.8798 [0.869, 0.888] | **0.9778** [0.975, 0.983] |
| ρ_error（合并计算，**仅作对照**） | 0.8448 | 0.9034 | 0.9420 | 0.9895 |
| 两源一致率（consensus coverage） | 0.9394 | 0.9583 | 0.9697 | 0.9773 |
| 共识准确率 | 0.8211 | 0.8221 | 0.8240 | 0.8231 |
| **准入层的投票增益**（20 种子中位数） | **0.0000** [−0.015, 0] | −0.0076 [−0.008, 0] | 0.0000 [−0.008, 0] | 0.0000 [0, 0] |

（α=0.25/0.50 分别共享 65 / 130 条样本；α=1 时源 A 完全包含源 B。全部为 20 种子 bootstrap。）

判定码：**`overlap_raises_agreement_not_value`**。三句话：

1. **重叠确实制造"伪共识"**——α 升到 1 时误差相关 0.655→0.978、一致率 0.939→0.977。
   这正是"多源一致"最容易被误读为"多源互证"的地方。
2. **但增益在所有 α 上都是非正的**——即把重叠度从 1 降到 0，**并没有**换来准入层变好。
3. **所以真正的瓶颈不是共享数据，而是方法同源**：两个源都是同一族模型（同一特征、同一算法族）训出来的，
   即使训练集完全不相交，误差结构仍然相似。**换数据集解决不了这个问题，只有换方法族（或换数据类型）才行。**

### 6.5 这条结论对框架是**不利**的，必须写进主文

- 它削弱了"多源独立性"作为卖点的力度：本 skill 的三源就是同一训练集上的三个模型（`CLAIMS.md` N3 已自我声明），
  而 6.4 说明**即便把数据集分开也不够**；
- 它把独立性从"数据层问题"提升为"**方法层问题**"——这对整个 ADMET 多模型共识领域都成立，
  而不仅是对本包成立。写进论文时这是**贡献**，写在材料里时这是**限制**，两者不冲突，但不得只写后者。
