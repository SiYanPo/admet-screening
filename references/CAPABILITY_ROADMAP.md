## 逐条分析与本文/本 skill 的关系

### 条件 2（外部复现）：证据最接近，但仍差一步

本 skill 已经具备的：
- `reproduce.sh`（--check / 表重算 / --full 三模式）
- 6 个 SHA-256 摘要，含**负向对照**（一位数字改动被检出）
- 干净 clone 实测 6/6（作者本机）
- `check_deposit_ready.py` 把"是否就绪"机器化

**差的不是工具，是"外部"。** 作者在自己的机器上 clone 自己仓库，不构成外部复现。要满足条件 2，需要：
1. 仓库公开（当前 BLOCKER：未 push）
2. Zenodo DOI（当前 BLOCKER）
3. **另一个人**（或另一个 CI 环境）跑出同样结果，并把结果留档

第 3 点的低成本路径：在 GitHub Actions 里跑 `reproduce.sh`，让 CI 日志成为公开的复现证据。这仍是"同一作者搭建的自动化"，但至少排除了本机环境污染。

**结论：条件 2 可以在不依赖他人的情况下推进到"CI 可复现"，但真正授予仍需第三方。**

### 条件 3（前瞻证据）：论文推进了一半

本文有预注册的 H1，且 H1 **失败**（诚实的负结果）。但 c\* 是事后推导的，所以：
- "H1 在参考点不成立"是前瞻证据（预注册 + 事后检验）✓
- "c\* = 0.209/0.260/0.515"不是（事后代数推导）

**一个能真正推进条件 3 的动作**：在做**新计算之前**先把预测写进带时间戳的文件，跑完再核对。

2026-11-25 的扩展端点计算已启动（8 个端点），错过了对它的预测窗口。但多模型稳健性实验（C）尚未启动，**对 C 可以补做**：

> 事前预测（写于实验之前）：c\* 在 RF / ExtraTrees / HistGradientBoosting 三族之间的相对变化应小于 20%；若超过，则"阈值是端点属性"的主张需降级为"阈值是端点×模型属性"。

这条预测会在 C 跑完后核对，命中与否都记为证据。**这是本轮唯一能真实推进条件 3 的动作。**

### 条件 1（第三方锚定）：最远

需要外部独立实现（而不是跑我的代码）。例如另一团队用自己的 pipeline 算 c\*，看是否落在我的置信区间内。

**当前阶段不现实**，除非有人主动合作。可做的前置：把 c\* 的定义写得足够清晰，使独立实现成为可能（`references/METHOD_COST_BOUNDARY.md` 第 3 节已做）。

### 条件 4（红线硬度）：有治理层但未接入

`adt/governance_ext/` 存在但标记为"实验性，不接主 CLI，需真实数据标定后按 SHADOW→ENFORCE 接入"。

要满足条件 4，需要至少一条红线从 SHADOW 转为 ENFORCE——即某个不安全输出被**强制**拦截并留下审计记录，且这个拦截在默认路径上生效（不是可选开关）。

## 5.0 的可行路径（按投入排序）

| 步骤 | 投入 | 能推进的条件 |
|---|---|---|
| **① 实验前记录预测（对 C 补做）** | 10 分钟 | 条件 3（几乎免费） |
| ② GitHub Actions 跑 `reproduce.sh` | 半天 | 条件 2 |
| ③ push + Zenodo DOI | 半天（账号动作） | 条件 2 |
| ④ 一条红线从 SHADOW 转 ENFORCE + 审计 | 2–3 天 | 条件 4 |
| ⑤ 找外部团队独立实现 c\* | 不可控 | 条件 1 |

**诚实结论**：即使全部做完 ①②③④，`CAPABILITY_LEVEL` 仍应为 `4.x`，因为条件 1 和 2 的"外部"属性不是作者能自我授予的。**5.0 是一个需要他人参与的状态，不是一个可以靠加班达到的里程碑。**

## 与论文的关系

论文对 skill 的贡献是**可引用性与证据留档**，不是能力等级：
- 论文提供了 c\* 的完整定义、适用边界与跨基线/跨模型证据（学术可信度）
